The **ocpp-ws-io** ecosystem is a modular suite of TypeScript packages, each solving a distinct challenge in EV charging infrastructure. Every package is designed to work independently _or_ seamlessly together.

<Callout type="info">
  **The proxy, the smart charge engine and the CLI are part of `ocpp-ws-io`** from 3.1.0 (on npm's `beta` tag until it is released): import `ocpp-ws-io/proxy` and `ocpp-ws-io/smart-charge`, and run the `ocpp` command. The separate packages `ocpp-protocol-proxy`, `ocpp-smart-charge-engine` and `ocpp-ws-cli` are deprecated; their last releases only re-export or run `ocpp-ws-io`.
</Callout>

## Install at a Glance

```bash
# Core RPC — client & server
npm install ocpp-ws-io

# Real-time dashboard & monitoring
npm install ocpp-ws-board

# Version translation proxy and smart charging math, in ocpp-ws-io from 3.1.0 (beta):
# import "ocpp-ws-io/proxy" and "ocpp-ws-io/smart-charge"
npm install ocpp-ws-io@beta

# CLI tools (no install required)
npx ocpp-ws-io@beta --help

# Logging
npm install voltlog-io
```

## Choosing the Right Package

| Need | Package |
|------|---------|
| Build a CSMS or charge point in Node.js | `ocpp-ws-io` |
| Monitor & inspect OCPP traffic in real-time | `ocpp-ws-board` |
| Support legacy 1.6 hardware on a 2.1 backend | `ocpp-ws-io/proxy` |
| Distribute grid power across multiple chargers | `ocpp-ws-io/smart-charge` |
| Test, mock, or debug OCPP traffic locally | the `ocpp` CLI (`ocpp-ws-io`) |
| Visualize OCPP sessions in the browser | `ocpp-ws-simulator` |
| Structured, performant logging | `voltlog-io` |

<Callout type="info">
Each package installs on its own; the proxy, the smart charge engine and the CLI come with `ocpp-ws-io`. You don't need the full ecosystem — pick only what your project requires.
</Callout>

## Interoperability

All packages share the same TypeScript type definitions for OCPP messages, meaning data flows between them without any manual type casting. See the [Architecture Overview](/docs#architecture-overview) for how they wire together.
